# AI-Assisted Provenance

**Status:** Documentation / research framework  
**Last reviewed:** 2026-10-05

## Purpose

GAIA 3.0 has been developed through a combination of human reasoning, research, external technical foundations, and assistance from multiple AI systems.

This document defines how that provenance should be described without collapsing materially different contributions into a single category such as "AI-generated."

The objective is **traceability without invented precision**.

## Contribution layers

### 1. Human origin and synthesis

Human contribution includes, where supported by project history and documentation:

- project goals and intended outcomes
- conceptual hypotheses
- architectural direction
- selection and combination of ideas
- acceptance or rejection of alternatives
- prioritization and sequencing
- interpretation of evidence
- decisions about what enters the repository
- review, testing, debugging, and maintenance

AI assistance does not by itself transfer ownership of these decisions to the AI system.

### 2. AI-assisted research

AI systems may assist with:

- finding and summarizing sources
- explaining technical concepts
- comparing approaches
- brainstorming alternatives
- identifying possible failure modes
- challenging assumptions
- organizing research questions
- translating ideas between technical domains

Research assistance is not equivalent to source authorship or independent verification.

### 3. AI-assisted implementation

AI systems may also assist with:

- code generation
- code modification
- refactoring
- test generation
- debugging
- documentation
- CI analysis
- implementation alternatives

Where exact line-level provenance is unavailable, the project should record the contribution category rather than inventing a precise attribution.

### 4. External foundations

GAIA builds on existing technologies, standards, algorithms, libraries, academic work, and open-source projects.

Examples include, but are not limited to:

- Rust and Cargo
- WebAssembly and WASI
- Wasmtime
- Git and GitHub
- GitHub Actions
- cryptographic primitives and libraries
- agent/tool interoperability concepts such as MCP

Use of an external foundation does not imply that GAIA originated that foundation.

## Multi-model assistance

GAIA research and development has involved assistance from multiple AI systems, including systems used for research, reasoning, implementation, critique, and comparative analysis.

Individual systems should not be presented as the sole source of GAIA merely because they contributed code, research, or suggestions.

When reliable history exists, specific contributions may be attributed more precisely. When it does not, attribution should remain qualified.

## Provenance chain

A useful GAIA provenance chain is:

**Source → Contribution → Transformation → Human Decision → Artifact → Evidence → Verification**

This distinguishes:

- where an idea or artifact came from
- what transformation occurred
- who made the consequential project decision
- what artifact resulted
- what evidence supports the artifact
- whether that evidence has been independently or procedurally verified

## Evidence-bounded attribution

GAIA should prefer:

> "This contribution is known to have been AI-assisted."

over an unsupported statement such as:

> "This exact line was written by model X."

Similarly, GAIA should not infer human authorship solely from the absence of AI metadata.

When provenance is uncertain:

**UNKNOWN → INSUFFICIENT EVIDENCE → HOLD / INVESTIGATE**

Unknown provenance must not be silently converted into certainty.

## Attribution is not verification

Provenance answers:

> **Where did this come from?**

Verification answers:

> **Does it actually hold up?**

These are independent dimensions.

A well-attributed claim can still be false.

A poorly attributed artifact can still be technically valid.

Therefore:

**Provenance ≠ Truth**  
**Attribution ≠ Verification**  
**AI assistance ≠ AI authorship**  
**Research assistance ≠ Source authority**  
**Code generation ≠ Validated implementation**

## Relationship to GAIA's evidence chain

The broader GAIA evidence model is:

**Observation → Interpretation → Claim → Evidence → Verification → Classification → State Transition**

AI-assisted work can participate at multiple points in this chain, but an AI-generated statement does not become evidence merely because it was generated by an AI system.

External sources, tests, reproducible observations, repository history, and human review should remain distinguishable.

## Recommended repository practice

For future work, provenance should be captured at the smallest useful level without creating unnecessary administrative burden.

Where practical, record:

- contribution type
- relevant source or system
- date or development phase
- resulting artifact
- human decision or review
- verification status
- uncertainty

Do not fabricate provenance records retroactively.

Historical reconstruction should explicitly distinguish:

- **documented**
- **strongly supported**
- **inferred**
- **unknown**

## Guiding principle

> **Preserve the path by which an artifact was created without pretending that the path is more certain than the evidence allows.**

GAIA's provenance system should make collaboration inspectable while preserving the distinction between human agency, AI assistance, external foundations, and technical verification.
